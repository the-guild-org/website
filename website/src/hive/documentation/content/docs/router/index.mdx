Hive Router is a high-performance [GraphQL Federation](/federation) router built with Rust. It
serves as the entry point for GraphQL requests in your federated setup, routing them efficiently
across your subgraph services.

## Why Hive Router?

When you're running a [federated GraphQL architecture](/federation), your router becomes one of the
most important pieces of your infrastructure. It needs to be fast, reliable, and handle real-world
production traffic without breaking a sweat. Here's what makes Hive Router a solid choice:

- **Speed matters.** Built with Rust, Hive Router is designed for performance and minimal resource
  usage. Your API calls won't get bogged down by router overhead.
- **Production-ready.** Rust's safety guarantees mean you get a router that handles concurrency well
  and won't crash under heavy load.
- **Open source, no strings attached.** MIT licensed and fully open source. Use it anywhere, modify
  it however you need, and avoid vendor lock-in.
- **Feature-complete.** Get security, traffic management, and modern federation features without
  hunting for plugins or add-ons.
- **Built-in observability.** Send traces to Hive Console or OTLP-compatible backends with
  OpenTelemetry support.

## Federation Compatibility

Hive Router works with the standard GraphQL Federation specification. We run comprehensive tests to
make sure it plays nicely with the rest of the federation ecosystem.

It serves Federation v2 supergraphs, from v2.0 through v2.9, including `@interfaceObject`,
[progressive `@override`](/docs/router/configuration/override_labels),
[`@context` and `@fromContext`](/docs/router/guides/contextual-arguments) and
[`@cost` and `@listSize`](/docs/router/security/demand-control). The
[compatibility table](/docs/router/compatibility) lists every feature and its status.

Check out our compliance testing:
**[Federation Gateway Audit](https://the-guild.dev/graphql/hive/federation-gateway-audit)**.

## Plugin System

Hive Router supports custom plugins written in Rust, giving you full control over the request
lifecycle. Plugins can intercept HTTP requests, modify GraphQL operations, hook into the query
planner, and much more - all with the performance and safety guarantees of Rust.

Learn how to build and integrate your own plugin:
**[Plugin System](/docs/router/customizations/plugin-system)**.

## Coprocessors

Hive Router also supports coprocessors, an external service interface for request-time
customization. Coprocessors are language-agnostic and can inspect, mutate, or short-circuit
requests at defined stages of the router lifecycle.

Learn more: **[Coprocessors](/docs/router/customizations/coprocessors)**.

## Subscriptions

Hive Router supports federated GraphQL subscriptions out of the box. Clients can receive real-time
data over [Server-Sent Events](/docs/router/subscriptions/sse),
[WebSockets](/docs/router/subscriptions/websockets), or
[HTTP streaming](/docs/router/subscriptions/multipart-http) - and the router handles protocol
negotiation automatically based on the client's `Accept` header. The transport used between the
router and your subgraphs is independent from the one your clients use, so each side can speak a
different protocol.

Federated entity resolution works the same way it does for queries - when a subscription event
arrives, the router queries any additional subgraphs needed to resolve entity fields and delivers
the complete result to the client.

The router can also receive events from subgraphs through
[HTTP callbacks](/docs/router/subscriptions/http-callback), and subscriptions to the same subgraph
share [multiplexed WebSocket connections](/docs/router/subscriptions/websockets).

Learn more: **[Subscriptions](/docs/router/subscriptions)**.

## Security

The router is the edge of your graph, so the controls that protect it are built in and configured in
the same YAML file:

- [JWT authentication](/docs/router/security/jwt-authentication), and authorization in the schema
  with [`@authenticated` and `@requiresScopes`](/docs/router/security/authorization)
- [Custom authorization policies](/docs/router/security/policy) with `@policy`, decided by a
  coprocessor
- [Demand control](/docs/router/security/demand-control) to reject operations that cost too much,
  and [operation complexity limits](/docs/router/security/operation-complexity) for depth, tokens
  and aliases
- [Persisted documents](/docs/router/security/persisted-documents), including
  [app deployments](/docs/schema-registry/app-deployments) from Hive Console
- [TLS and mutual TLS](/docs/router/security/tls) towards clients and towards subgraphs
- [Subgraph error masking](/docs/router/security/error-masking), so internal details do not reach
  clients
- [CORS](/docs/router/security/cors), [CSRF prevention](/docs/router/security/csrf) and
  [introspection control](/docs/router/security/introspection)

## Traffic Shaping and Reliability

Hive Router decides how requests move between clients and subgraphs:

- [Circuit breakers](/docs/router/guides/performance-tuning#circuit-breaker) stop sending requests
  to a subgraph that is failing
- [Request deduplication](/docs/router/guides/performance-tuning#request-deduplication), timeouts,
  connection pools, compression and HTTP/2 are tuned per subgraph in
  [traffic shaping](/docs/router/configuration/traffic_shaping)
- [Dynamic subgraph routing](/docs/router/guides/dynamic-subgraph-routing) sends a request to a
  different subgraph instance per tenant, region or feature flag
- [Header rules](/docs/router/guides/header-manipulation) propagate, add, remove and rewrite headers
  in both directions
- The supergraph and persisted documents can be loaded from
  [S3-compatible object storage](/docs/router/configuration/storages)

## Observability

In production, you need to see what happens inside your API. Hive Router has built-in observability
features to help you find problems and keep your GraphQL API stable.

Hive Router supports tracing and metrics. Tracing helps you follow one request across the router and
subgraphs, so you can find where a request is slow or fails. Metrics help you monitor traffic, error
rate, latency, cache behavior, and supergraph reloads over time.

You can send [traces](/docs/router/observability/tracing) to Hive Console, to OTLP-compatible
backends, or to Datadog through its
[native tracer](/docs/router/observability/tracing#send-traces-through-native-datadog-tracing).
[Metrics](/docs/router/observability/metrics) are exported to OTLP-compatible backends or exposed on
a Prometheus scrape endpoint. This lets you use the monitoring tools your team already has.

[Logs](/docs/router/observability/logging) are structured, with one summary line per request at the
default level. [Usage reporting](/docs/router/observability/usage_reporting) sends schema usage to
Hive Console, where it drives breaking change detection based on real traffic.

Learn more: **[OpenTelemetry Tracing](/docs/router/observability/tracing)**,
**[OpenTelemetry Metrics](/docs/router/observability/metrics)** and
**[Logging](/docs/router/observability/logging)**.
