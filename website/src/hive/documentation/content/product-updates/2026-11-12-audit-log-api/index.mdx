Until now, getting the [audit log](/docs/schema-registry/management/audit-logs) out of Hive Console
meant exporting a CSV file from the organization settings. That works for an occasional review, but
security teams want audit events in the same place as everything else: their SIEM.

The new **audit log API** makes that possible. It's a single HTTP endpoint that your SIEM (Splunk,
Microsoft Sentinel, Elastic, Datadog, …) or any script can poll to continuously ingest your
organization's audit log.

```bash
curl -H "Authorization: Bearer $HIVE_ACCESS_TOKEN" \
  "https://api.graphql-hive.com/audit-log/v1/events?limit=100"
```

## How It Works

- **Cursor-based pagination**: every response returns a `nextCursor`. Store it, pass it back on the
  next request, and you'll only receive events you haven't seen yet. A `Link: rel="next"` header is
  included too, for clients that follow links.
- **No gaps**: events are returned oldest first, so you never miss an event. Delivery is
  at-least-once; deduplicate on the event `id`.
- **Stable, versioned events**: every event uses a versioned JSON envelope with the event type, the
  actor (user, organization access token or system), its IP address and user agent, and
  event-specific metadata.
- **Filtering and backfill**: use `eventTypes` to only fetch the events you care about (e.g.
  `USER_SIGNED_IN,USER_SIGN_IN_FAILED`), and `since` to choose how far back a new integration
  starts. Without it, you get the full year of retained history.

## Get Started

1. In your organization **Settings**, create an
   [organization access token](/docs/schema-registry/management/access-tokens) with the new
   **Describe audit log** (`auditLog:describe`) permission.
2. Point your SIEM's HTTP pull input (or your own script) at
   `https://api.graphql-hive.com/audit-log/v1/events` and send the token as a bearer token.
3. Poll every minute, following `nextCursor`.
