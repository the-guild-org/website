[`@graphql-codegen/cli`](https://the-guild.dev/graphql/codegen) v8.0 and new plugin majors are now
available, bumping minimum supported versions and removing deprecated options and APIs.

- Minimum Node.js is now `>=22.18.0`, and `graphql` below v16 is no longer supported
- `@graphql-tools/*` dependencies and `graphql-config` move to their latest majors
- `emitLegacyCommonJSImports` is removed in favour of `importExtension`
- `config.generates` is correctly typed and handled as `ConfiguredOutput[]`
- Plugin `validate` now matches the `plugin` function signature

## Why `v8`?

Most of this release is housekeeping: dropping old Node.js and `graphql` versions we no longer test
against, picking up the latest `@graphql-tools` and `graphql-config` majors, and removing options and
types that had been deprecated or silently broken for a while. A couple of changes can still change
the shape of your generated code - notably the `code-file-loader@9` document pluck default and the
`emitLegacyCommonJSImports` removal below - so a few of the changes do need action on your side.

## Breaking changes

### Node.js and `graphql`

The new `@graphql-tools/*` majors require Node.js `>=22.18.0`, so the CLI and all official packages
raise their `engines.node` to match. `graphql` v14 and v15 are no longer supported - the peer range is
now `^16.0.0 || ^17.0.0`.

### `@graphql-tools/*` and `graphql-config` updates

All `@graphql-tools/*` dependencies move together and now require `@graphql-tools/utils@^13`, and
`graphql-config` is updated to v6. If you have custom loaders, plugins, or `graphql-config`
extensions, make sure they're compatible with these versions.

<Callout>
  `code-file-loader@9` extracts documents marked with `#graphql` by default, so you may see new
  documents picked up that weren't before. Set `pluckConfig: { gqlHashComment: '' }` to keep the
  previous behaviour.
</Callout>

### `emitLegacyCommonJSImports` is replaced by `importExtension`

The `emitLegacyCommonJSImports` config option and `--emit-legacy-common-js-imports` CLI flag are
removed across the CLI, `plugin-helpers`, `visitor-plugin-common`, `gql-tag-operations`,
`typescript-operations`, `client-preset`, and `graphql-modules-preset`. `importExtension` (or
`--import-extension`) is now the only way to control the extension of relative imports:

```diff title="codegen.ts"
 const config: CodegenConfig = {
   config: {
-    emitLegacyCommonJSImports: false
+    importExtension: '.js'
   }
 }
```

If you never set `emitLegacyCommonJSImports: false`, there's nothing to change.

### `config.generates` is now handled correctly as an array

`generates` values were previously typed as `ConfiguredOutput | ConfiguredPlugin[]`, but the array
form always threw at runtime. They're now typed as `ConfiguredOutput | ConfiguredOutput[]`, so a
plugin-name array such as `['typescript-operations']` no longer type-checks and still throws
`Invalid Codegen Configuration` - use `{ plugins: ['typescript-operations'] }` instead. For an
array of output objects, only the first element is used today - running them sequentially for a
single output is planned for an upcoming release.

### Plugin API changes

A few changes affect custom plugin authors:

- `validate` now receives `{ outputFile, allPlugins, pluginContext }` as its fourth argument, matching
  the `plugin` function signature, instead of separate positional arguments.
- `generate()` is typed as `Promise<FileOutput[] | void>` instead of collapsing to `any`.
- `plugin-helpers` removes `isOutputConfigArray`, `isConfiguredOutput`, and `normalizeImportExtension`,
  and `normalizeOutputParam` now always returns `ConfiguredOutput[]`.
- The `schema-ast` plugin's `commentDescriptions` option is removed - it has had no effect since
  `graphql` 16.

Read the full [v8 migration guide](https://the-guild.dev/graphql/codegen/docs/migration/from-7-0) for
every breaking change, with before/after snippets.

## Upgrading

```sh npm2yarn
npm i -D @graphql-codegen/cli@latest @graphql-codegen/typescript@latest @graphql-codegen/typescript-operations@latest @graphql-codegen/client-preset@latest
```

<Callout type="warning">
  GraphQL Codegen packages share a lot of code internally, so if you explicitly install other official
  packages (such as `@graphql-codegen/visitor-plugin-common` or `@graphql-codegen/plugin-helpers`) in
  the same repo, update them at the same time to avoid unexpected issues.
</Callout>
